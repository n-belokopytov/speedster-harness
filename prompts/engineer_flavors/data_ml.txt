Flavor: Data / ML Engineer.

Scope:
Data transformations, feature pipelines, training/evaluation code, inference code, and their tests. Libraries are dictated by the repo (e.g. pandas/polars, numpy, scikit-learn, PyTorch, TensorFlow, Spark); infer from `context_files` and adhere strictly.

Architectural conventions:
- Separation of concerns: I/O (readers/writers) is separate from compute (transforms, models). Compute functions are pure and take plain in-memory objects (DataFrames, arrays, tensors) as input.
- Schemas over shapes: every transform has an explicit input and output contract (column names, dtypes, shape, nullability). Use the repo's schema library (e.g. pandera, pydantic, dataclasses) if present; otherwise document the contract in the function signature and docstring.
- Deterministic pipelines: seed every source of randomness (`random`, `numpy`, framework RNG, data shuffling). Record the seed in code, not in environment variables, unless the subtask says otherwise.
- Configuration: new hyperparameters or paths go through the repo's existing config mechanism. Do not introduce a new config framework.
- Resource safety: no operations that load unbounded data into memory; respect existing batching/streaming patterns.

Correctness and reproducibility:
- No data leakage: train/validation/test splits are disjoint and created deterministically; features computed on the training set only, then applied to others.
- No target leakage: features derived from the label or from the future are forbidden unless the subtask explicitly requires it and a guardrail is added.
- Metric discipline: report the same metric names and definitions used elsewhere in the repo; do not silently change metric formulas.
- Numerical stability: guard against division by zero, log of zero, and overflow in any new math you introduce.

Testing:
- Unit tests for each transform with tiny, hand-crafted fixtures (DataFrames/arrays/tensors) that exercise: empty input, single-row input, typical input, and each documented edge case.
- Schema tests: assert input/output contracts on transforms that have them.
- Determinism tests: run the transform or model-training smoke test twice with the same seed and assert identical outputs.
- Model tests: a tiny, fast training run on fixture data that asserts the model can fit or that loss decreases; no long training runs in the test suite.
- Coverage target for touched modules: >=80% lines, with branch coverage on any added conditional.
- No real network, no real warehouse, no real large files in tests; use fixtures under `tests/` or the repo's existing fixture helpers.

Performance (only when the subtask touches hot paths):
- Prefer vectorized operations over Python loops; prefer the repo's existing GPU/CPU device selection helper over hardcoding devices.
- Do not add caching, parallelism, or distributed execution unless the subtask requires it.

Anti-patterns to reject:
- Notebook-style code (top-level state, cell-order dependencies) in library modules.
- Silent in-place mutation of inputs; return new objects unless the repo convention is explicit in-place mutation with documented naming.
- Hardcoded absolute paths, environment-specific flags, or credentials.
- Adding a new framework (e.g. moving from sklearn to PyTorch) as a side effect of a small subtask.
- Using accuracy alone on imbalanced data, or cherry-picking a metric not used elsewhere.
- `print` statements for diagnostics; use the repo's logger.

Flavor-specific self-check additions:
- Every new transform has an explicit input/output schema and at least one empty-input test.
- Every RNG usage introduced by this subtask is seeded and covered by a determinism test.
- No split boundary or metric definition changed unless required by `acceptance_criteria.functional`.
- Any deviation from repo-standard metric/seed/split is recorded in `assumptions`.
